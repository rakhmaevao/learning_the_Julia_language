# JuliaLeet — тренажёр LeetCode на Julia

Локальный тренажёр: 576 задач LeetCode с тестами, каждая — в своей папке,
плюс веб-интерфейс с таблицей задач, фильтрами и календарём прогресса.

Задачи, условия, тесты и эталонные решения импортированы из
[JuliaCN/LeetCode.jl](https://github.com/JuliaCN/LeetCode.jl) (MIT).

## Быстрый старт

```bash
./leet ui             # веб-интерфейс на http://127.0.0.1:8080 (откроется в браузере)
./leet list --status=todo --difficulty=Easy
./leet path 1         # путь к папке задачи
./leet test 1         # прогнать тесты; если зелено — задача автоматически отмечается решённой
./leet stats          # сводка прогресса в терминале
```

Первый запуск компилирует пакеты (~1 минута), дальше быстро.

## Как устроена одна задача

```
problems/0001-two-sum/
├── README.md      условие задачи (markdown)
├── meta.toml      метаданные + прогресс + история прогонов
├── template.jl    исходный шаблон: сигнатуры функций с заглушкой error(...)
├── solution.jl    ← ваш файл, здесь пишется решение
├── test.jl        тесты (@testset), их менять не нужно
└── reference.jl   эталонное решение (спойлер!)
```

`solution.jl` и `test.jl` выполняются в отдельном анонимном модуле, где уже
подключён `LeetKit.Support` (структуры `ListNode`, `TreeNode`, функции
`next_perm!`, `mat_fast_mul`, а также `DataStructures`, `OffsetArrays`, `Dates`).
Ничего дополнительно импортировать не нужно.

### Рабочий цикл

1. Выбрать задачу в UI или через `./leet random --difficulty=Easy`.
2. `./leet open 15` — открыть папку (в `$EDITOR`, иначе через `xdg-open`).
3. Писать код в `solution.jl`.
4. `./leet test 15` — прогнать тесты. На шаблоне они, конечно, падают.
5. Зелёные тесты → в `meta.toml` пишется `status = "solved"`, дата, число попыток,
   лучшее время и память; прогон попадает в историю и в календарь.

Полезное:

* `./leet test 15 --reference` — проверить, что эталон проходит тесты (свой файл не трогается).
* `./leet solve 15 --date=2026-08-01 --note="решил на бумаге"` — отметить вручную.
* `./leet reset 15` — вернуть `solution.jl` к шаблону (старый файл → `solution.jl.bak`).
* `./leet new 9001 my-task --title="Своя задача" --difficulty=Medium` — каркас собственной задачи.

## Веб-интерфейс

`./leet ui [--port=8080] [--no-open]`

* **Задачи** — таблица со статусом, номером, названием, сложностью, темами,
  числом попыток, лучшим временем и датой решения. Фильтры по тексту, сложности,
  статусу и теме, сортировка по любому столбцу, кнопка «🎲 Случайная».
* Клик по строке — карточка задачи: условие, путь к папке (копируется одной кнопкой,
  открывается в файловом менеджере), запуск тестов прямо из браузера, отметка
  «решено», сброс решения, заметки, история прогонов, вкладки «Моё решение»,
  «Тесты» и скрытый по умолчанию «Эталон».
* **Прогресс** — карточки по сложностям, серия дней, календарь-хитмап: цвет клетки =
  сложность решённой в этот день задачи (градиент, если задач несколько), обводка =
  были прогоны тестов без решения. Ниже — лента последних дней.

Данные в UI берутся из тех же `meta.toml`, что и CLI, — можно свободно
переключаться между терминалом и браузером, файлы всегда источник правды.

## meta.toml

```toml
id = 1
slug = "two-sum"
title = "Two Sum"
difficulty = "Easy"
categories = ["Array", "Hash Table"]
entrypoints = ["two_sum"]      # функции, которые ждут тесты

[progress]
status = "solved"              # todo | attempted | solved
solved_at = "2026-08-20"
first_solved_at = "2026-08-20" # эта дата попадает в календарь
attempts = 3
best_time_ns = 4184786
best_bytes = 133952
notes = ""

[[runs]]                       # история последних 60 прогонов
at = "2026-08-20T08:45:16"
mode = "solution"
passed = true
n_pass = 3
```

Файл можно править руками — CLI и UI подхватят изменения.

## Служебное

* `LeetKit/` — пакет с логикой: `Support.jl` (общие структуры), `Meta.jl` (meta.toml),
  `Runner.jl` (запуск тестов в отдельном процессе с таймаутом), `Stats.jl` (агрегаты),
  `Server.jl` + `assets/index.html` (веб-интерфейс), `CLI.jl` (команды).
* `tools/import_problems.jl` — импорт задач из клона LeetCode.jl:
  `julia --project=. tools/import_problems.jl /путь/к/LeetCode.jl` (без `--force`
  существующие `solution.jl` и `meta.toml` не трогаются).
* Тесты запускаются в отдельном процессе Julia с таймаутом (по умолчанию 60 с),
  так что бесконечный цикл в решении не подвесит UI.

## Известное

Часть эталонных решений из upstream не проходит собственные тесты на Julia 1.12
(см. `docs/reference-audit.md`). Условие и тесты у таких задач рабочие — решать их
можно, просто «проверить эталон» покажет ошибку.
